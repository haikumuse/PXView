### 📊 DSView 主线程性能瓶颈分析报告

#### 1. 核心瓶颈：同步文件 I/O 阻塞（高优先级）
**现象**：在侧边栏切换、动画结束或配置更改时，界面会出现明显的瞬时卡顿。
*   **分析**：通过火焰图发现，`AppConfig::SaveFrame()` 被频繁调用（例如在 `SlidingDrawer::drawerClosed` 和 `MainWindow::on_side_bar_dock_clicked` 中）。
*   **深层原因**：`SaveFrame` 内部调用了 `QSettings` 的析构或同步操作，这会触发系统级的 `fdatasync`（文件同步到硬盘）。这是一个**磁盘 I/O 密集型任务**，在主线程执行会直接导致事件循环挂起几百毫秒。
*   **动画关联**：极其严重的是，动画驱动器（`advanceAnimation`）有时会间接触发配置保存，导致动画过程中出现严重的“跳帧”。

#### 2. UI 组件的频繁重创与销毁（中高优先级）
**现象**：拖动测量光标或执行测量任务时，主界面响应变慢。
*   **定位**：`MeasureDock::reCalc()` 及其调用的 `build_cursor_pannel()`。
*   **问题所在**：
    *   该函数在光标移动时被高频调用（`cursor_moved()` 信号连接）。
    *   它每次都会调用 `deleteLater()` 销毁旧部件，并重新 `new` 出 `XToolButton`、`QPushButton` 和 `QLabel`。
    *   每次创建新部件都会重新加载图标（`QIcon(iconPath + "/del.svg")`），涉及 **SVG 解析和位图化**，这在绘制循环中非常昂贵。
*   **建议**：改用“池化”或“更新”机制，仅在数量变化时增减部件，平时仅更新文本内容。

#### 3. 波形渲染点的实时计算压力（持续负载）
**现象**：当显示的波形通道较多或缩放比例较大时，整体帧率下降。
*   **分析**：`pv::view::Viewport::paintEvent` 触发的 `LogicSnapshot::get_display_edges`。
*   **瓶颈点**：
    *   该函数在绘图过程中执行。它需要获取 `_mutex` 锁，并遍历复杂的 Mipmap 树来寻找波形跳变点。
    *   当信号密集时，该算法的计算复杂度会直接反映在主线程的 CPU 占用上。
*   **建议**：将渲染路径所需的 `edges` 数据预计算化，或移至工作线程计算后通过 `QImage` 离屏绘制。

#### 4. 初始化阶段的 Python 解码器加载（启动性能）
**现象**：程序启动或重新加载设备时，界面“白屏”或无响应。
*   **分析**：`srd_decoder_load_all` 及其相关的 `py_import_by_name` 占用了大量的 samples。
*   **原因**：Python 解释器的初始化和大量解码器插件的加载完全在主线程同步执行。
