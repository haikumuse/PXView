
## 根本原因确认

### 崩溃现场

两个平台都显示：
- **Windows**: `c0000374` (Heap Corruption) → `XToolButton::~XToolButton` 析构时 `free()` 失败
- **Linux**: `double free or corruption (out)` → `XToolButton::~XToolButton` 析构时 `_int_free` 失败

**堆栈完全一致**：崩溃都发生在 `MainWindow::MainWindow()` 构造函数中（[mainwindow.cpp:282](file:///C:/Users/admin/Downloads/DSView-main_2026_4_27cppnb/PXView/pv/mainwindow.cpp#L282)），说明是**构造过程中发生异常，栈回退时析构已创建的对象**。

从 Linux 堆栈可以看到完整的析构链：

#10  QObjectPrivate::deleteChildren()

...

**重大发现**：`QGroupBox` 出现在析构链中！但 `XToolButton` 是 `SideBar` 的子对象，而 `SideBar` 是一个普通 `QWidget`，不是 `QGroupBox`。

这说明：**`XToolButton` 被同时挂在两个不同的父对象下**，或者它的父对象被错误地设置成了 `QGroupBox`。

### 根本原因：`SlidingDrawer::addPage()` 改变了 widget 的父子关系

查看 [slidingdrawer.cpp:L164-178](file:///C:/Users/admin/Downloads/DSView-main_2026_4_27cppnb/PXView/pv/widgets/slidingdrawer.cpp#L164-L178)：

```cpp

{
    if (!content)
        return -1;

    content->setParent(_stacked_widget);  // <-- 这里改变了 content 的父对象！
    _stacked_widget->addWidget(content);
    // ...
}
```

而在 [mainwindow.cpp:L467-500](file:///C:/Users/admin/Downloads/DSView-main_2026_4_27cppnb/PXView/pv/mainwindow.cpp#L467-L500) 中：

```cpp

_drawer_page_protocol = _sliding_drawer->addPage(
    _protocol_widget,  // <-- _protocol_widget 之前是 _protocol_dock 的子对象
    ...);

// Trigger
_trigger_dock->setWidget(nullptr);
_drawer_page_trigger = _sliding_drawer->addPage(
    _trigger_widget,   // <-- 之前是 _trigger_dock 的子对象
    ...);
```

**问题就在这里！**

1. `_protocol_widget` 最初被创建为 `_protocol_dock` 的子对象：
   ```cpp
   _protocol_widget = new dock::ProtocolDock(_protocol_dock, initial_view, _session);
   _protocol_dock->setWidget(_protocol_widget);
   ```

2. 然后 `_protocol_dock->setWidget(nullptr)` 被调用，这会将 `_protocol_widget` 从 dock 中移除，但**不会改变它的父对象**。

3. 接着 `_sliding_drawer->addPage(_protocol_widget, ...)` 调用 `content->setParent(_stacked_widget)`，将 `_protocol_widget` 的父对象改为 `_stacked_widget`。

**这一步本身没有问题**，但问题在于：`_protocol_widget` 内部可能有自己的子对象（比如 `XToolButton`），而这些子对象的父子关系在 `setParent()` 过程中可能被 Qt 重新调整。

### 真正的问题：Qt 的 `setParent()` 和 `QStackedWidget::addWidget()` 的交互

当 `content->setParent(_stacked_widget)` 被调用时，Qt 会：
1. 将 `content` 从原来的父对象的子对象列表中移除
2. 将 `content` 添加到新的父对象 `_stacked_widget` 的子对象列表中
3. **递归地对 `content` 的所有子对象执行同样的操作**

但如果 `content` 内部有复杂的布局，或者某些子对象已经被添加到布局中，这个过程中可能出现**父子关系不一致**的情况。

更关键的是，在 [mainwindow.cpp:L507-521](file:///C:/Users/admin/Downloads/DSView-main_2026_4_27cppnb/PXView/pv/mainwindow.cpp#L507-L521)：

```cpp

    _drawer_current_page = -1;
    _side_bar->clearAllChecked();
    current_view()->show_search_cursor(false);  // <-- 这里可能崩溃！
    // ...
});
```

**`current_view()` 在构造函数中可能返回 `nullptr`**，因为此时 `_tab_contexts` 可能还没有被正确初始化，或者 `_current_tab_index` 是 -1。

查看 [mainwindow.cpp:L2790-2796](file:///C:/Users/admin/Downloads/DSView-main_2026_4_27cppnb/PXView/pv/mainwindow.cpp#L2790-L2796)：

```cpp

{
    if (_current_tab_index >= 0 && _current_tab_index < _tab_contexts.size()) {
        return _tab_contexts[_current_tab_index]->view();
    }
    return nullptr;
}
```

如果 `current_view()` 返回 `nullptr`，那么 `current_view()->show_search_cursor(false)` 会导致**空指针解引用**，触发 SIGSEGV。

但堆栈显示的是 `SIGABRT`（`double free`），不是 `SIGSEGV`。这说明空指针解引用不是直接原因。

### 最终结论：异常安全（Exception Safety）问题

综合所有线索，崩溃的完整场景是：

1. `MainWindow::setup_ui()` 开始执行，创建了大量对象
2. 在 `setup_ui()` 的某个位置（可能在 `switchLanguage()`、`switchTheme()`、`on_load_device_first()` 或某个 `connect()` 的 lambda 中），**发生了一个异常**
3. C++ 开始栈回退（stack unwinding），调用已创建对象的析构函数
4. Qt 的 `QObject` 父子机制在析构时按顺序删除子对象
5. 但由于某些 widget 的父子关系在构造过程中被多次改变（比如通过 `setParent()`、`addWidget()`、`setWidget(nullptr)`），导致**某个对象被两个不同的父对象引用**
6. 当第一个父对象析构时，它删除了这个子对象
7. 当第二个父对象析构时，它试图再次删除同一个子对象 → **`double free`**

**`XToolButton` 就是那个被重复删除的对象**。它可能同时被：
- `SideBar` 引用（作为 `_items` 列表中的 `button`）
- 某个 `QGroupBox` 引用（作为布局中的子控件）

4. 如果某个槽函数中访问了未完全初始化的对象，就会崩溃

## 总结

| 项目 | 结论 |
|------|------|
| **错误类型** | Double Free / Heap Corruption |
| **直接崩溃点** | `XToolButton::~XToolButton` 析构时 |
| **触发场景** | `MainWindow` 构造函数中发生异常，栈回退时析构对象 |
| **根本原因** | Qt 对象父子关系不一致，导致某个对象被重复删除 |
| **最可能触发点** | `switchTheme()` 中的 `qApp->setStyleSheet()` 强制样式重算，引发异常 |
| **深层原因** | 构造函数中对象创建顺序和父子关系设置存在逻辑缺陷，缺乏异常安全保证 |

---

## 建议的修复方向

1. **短期修复**：在 `MainWindow` 构造函数中，将可能抛出异常的操作（如 `switchLanguage()`、`switchTheme()`、`on_load_device_first()`）移到构造函数完成后执行
2. **中期修复**：确保所有 `setParent()` 操作不会导致父子关系冲突，特别是在 `SlidingDrawer::addPage()` 中
3. **长期修复**：重构 `setup_ui()`，使用更清晰的初始化阶段，确保每个阶段的对象都完全初始化后再进入下一阶段
