# PXView 项目架构与数据流全面分析

## 一、项目概述

PXView 是一款基于 Qt5 的逻辑分析仪/示波器桌面 GUI 应用程序，版本 v1.4.9。它基于 DSView（DreamSourceLab）和 PulseView 开发，专门为 PX-Logic 系列硬件（如 PX-Logic U3 channel 32、U3 channel 16 Pro/Plus/Base 等）设计。项目使用 C++11 和 C99 编写，构建系统为 CMake。

**核心依赖**：Qt5、glib-2.0、Python3、FFTW、libusb-1.0、zlib、Boost

## 三、核心架构层次

### 3.1 应用核心层 (appcore)

这是整个应用的"大脑"，包含四个关键类：

**[AppControl](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/appcore/appcontrol.h)** - 单例应用控制器
- 负责初始化 libsigrok 和 libsigrokdecode
- 持有 `SigSession` 实例
- 管理应用生命周期（Init -> Start -> Stop -> UnInit）

**[SigSession](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/appcore/sigsession.h)** - 信号会话（最核心的类）
- 实现 `IMessageListener` 和 `IDeviceAgentCallback` 接口
- 管理所有信号（`_signals`）、解码轨迹（`_decode_traces`）、频谱轨迹（`_spectrum_traces`）
- 管理双缓冲数据（`_view_data` / `_capture_data`）
- 控制采集流程（开始/停止/重复采集）
- 接收硬件数据回调（`data_feed_in` -> `feed_in_logic/dso/analog`）
- 管理解码任务队列（`_decode_tasks`）和解码线程（`_decode_thread`）

**[DeviceAgent](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/appcore/deviceagent.h)** - 设备代理
- 封装 libsigrok 的设备操作（开始/停止采集、配置读写）
- 支持三种设备类型：USB硬件、Demo虚拟设备、文件回放
- 提供类型安全的配置读写方法（get/set_config_uint64、bool、double 等）

**[MainWindow](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/appcore/mainwindow.h)** - 主窗口
- 实现 `ISessionCallback`、`IMainForm`、`ISessionDataGetter`、`IMessageListener`
- 持有 View、各种 Dock、Toolbar
- 处理 JSON 配置文件的加载/保存

### 3.2 数据层 (data)

数据层是波形和协议数据的存储核心：

**[SessionData](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/appcore/sigsession.h#L103-L130)** - 会话数据容器
```
SessionData {
    LogicSnapshot   logic;    // 逻辑分析仪数据
    AnalogSnapshot  analog;   // 模拟通道数据
    DsoSnapshot     dso;      // 示波器数据
    _cur_snap_samplerate;
    _cur_samplelimits;
}
```

**[Snapshot](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/snapshot.h)** - 快照基类
- 管理采样率、样本数、通道数、内存分配状态
- 线程安全（`std::mutex _mutex`）
- 支持环形缓冲区模式

**[LogicSnapshot](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/logicsnapshot.h)** - 逻辑数据快照（最复杂的数据结构）
- 采用**四级树形索引结构**（ScaleLevel=4, ScalePower=6）
- RootNode 结构：`tog`（翻转位图）、`first`/`last`（首尾样本）、`lbp[64]`（叶块指针数组）
- 叶块空间 = (Scale + Scale^2 + Scale^3 + Scale^4) / 8 = 43690 字节
- 每个叶块包含 2^24 = 16M 个样本
- 支持**环形缓冲区模式**（loop mode），用于流式采集
- 提供 `get_samples()`、`get_nxt_edge()`、`get_pre_edge()`、`get_display_edges()` 等查询方法
- 支持模式搜索（`pattern_search`）

**[AnalogSnapshot](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/analogsnapshot.h)** - 模拟数据快照
- 使用连续内存块存储（`void *_data`）
- **10级包络线缓存**（`Envelope _envelope_levels[DS_MAX_ANALOG_PROBES_NUM][ScaleStepCount]`）
- 包络线用于快速缩放渲染，避免逐样本绘制
- 支持分块存储（LeafBlockPower=21，每块 2M 样本）

**[DsoSnapshot](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/dsosnapshot.h)** - 示波器数据快照
- 按通道分离存储（`std::vector<uint8_t*> _ch_data`）
- 同样有 10 级包络线缓存
- 支持 Vrms/Vmean 计算、阈值设置

**[DecoderStack](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/decoderstack.h)** - 解码栈
- 一个协议对应一个 DecoderStack
- 持有解码器链表（`std::list<decode::Decoder*> _stack`）

- 管理解码行数据（`std::map<const decode::Row, decode::RowData*> _rows`）
- 后台线程执行解码（`begin_decode_work()` / `decode_data()`）
- 通过 `annotation_callback` 接收 Python 解码器的输出

**[DecoderModel](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/decodermodel.h)** - Qt 表格模型
- 继承 `QAbstractTableModel`
- 为 ProtocolDock 的 QTableView 提供数据

**[SpectrumStack](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/spectrumstack.h)** - 频谱数据栈
- 使用 FFTW3 进行 FFT 计算

**[MathStack](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/mathstack.h)** - 数学运算栈

## 四、波形数据采集、存储与处理流程

### 4.1 数据采集流程

```
USB 硬件 → libusb 传输 → libsigrok 驱动 (pxlogic.c / dsl.c)
    → sr_datafeed_packet 回调
    → SigSession::data_feed_callback (静态方法)
    → SigSession::data_feed_in
    → feed_in_logic / feed_in_dso / feed_in_analog
```

详细流程：

1. **硬件初始化**：`DeviceAgent::start()` 调用 libsigrok 的 `sr_session_start()`
2. **数据传输**：libsigrok 通过 libusb 批量传输获取数据，支持 USB 2.0/3.0
3. **数据包回调**：`data_feed_in()` 根据 `packet->type` 分发：
   - `SR_DF_HEADER` -> `feed_in_header()` - 采集开始
   - `SR_DF_META` -> `feed_in_meta()` - 元数据（采样率等）
   - `SR_DF_TRIGGER` -> `feed_in_trigger()` - 触发位置
   - `SR_DF_LOGIC` -> `feed_in_logic()` - 逻辑数据
   - `SR_DF_DSO` -> `feed_in_dso()` - 示波器数据
   - `SR_DF_ANALOG` -> `feed_in_analog()` - 模拟数据
   - `SR_DF_END` -> 采集结束，标记 `capture_ended()`

4. **数据存储**：
   - 首个数据包：`first_payload()` 分配内存
   - 后续数据包：`append_payload()` 追加数据
   - 逻辑数据使用树形索引 + 环形缓冲区
   - DSO/模拟数据使用连续内存 + 包络线缓存

### 4.2 双缓冲机制

SigSession 维护**双缓冲**结构：

```cpp
SessionData *_view_data;      // 当前显示的数据
SessionData *_capture_data;   // 当前采集的数据
std::vector<SessionData*> _data_list;  // 两个 SessionData 对象
```

- **单次采集模式**：`_view_data == _capture_data`，同一缓冲区
- **重复采集模式**：交替使用两个缓冲区，采集完成后交换
  - 新采集开始时，`_capture_data` 切换到另一个缓冲区
  - 采集结束后，`_view_data = _capture_data`，更新显示
- **流式模式**：使用环形缓冲区，实时刷新

### 4.3 采集模式

```cpp
enum DEVICE_COLLECT_MODE {
    COLLECT_SINGLE = 0,  // 单次采集
    COLLECT_REPEAT = 1,  // 重复采集（双缓冲）
    COLLECT_LOOP = 2,    // 循环采集（环形缓冲区）
};
```

## 五、协议解码数据存储与处理流程

### 5.1 解码流程

```

    → DecoderStack::begin_decode_work()
    → DecoderStack::execute_decode_stack()
    → srd_session_send (将逻辑数据送入 Python 解码器)
```

- **解码任务队列**：`_decode_tasks` 管理解码任务，`_decode_thread` 后台执行
- **子解码器**：支持解码器堆叠（如 SPI -> 以太网 -> IP -> TCP）
- **解码区域**：支持指定解码的样本范围（`_decode_start` / `_decode_end`）

## 六、缓存机制

### 6.1 逻辑数据缓存 - 树形 Mipmap

LogicSnapshot 使用**四级树形索引**实现快速边缘查找：
- Level 0: 原始数据（64位对齐）
- Level 1-3: 翻转位图（每级压缩 64 倍）
- `calc_mipmap()` 在数据写入时计算各级索引
- `get_nxt_edge()` / `get_pre_edge()` 利用索引快速跳转

### 6.2 模拟/DSO 数据缓存 - 包络线

AnalogSnapshot 和 DsoSnapshot 使用**10级包络线缓存**：
- 每级压缩 `EnvelopeScaleFactor` 倍
- 存储每个区间的 min/max 值
- `get_envelope_section()` 根据像素密度选择合适的包络级别
- 避免在缩放视图中逐样本绘制

### 6.3 双缓冲缓存

两个 `SessionData` 对象交替使用，确保采集和显示互不干扰。

### 6.4 解码结果缓存

- `RowData` 持有所有 `Annotation` 对象的有序列表
- `AnnotationResTable` 管理注解的字符串资源，避免重复存储
- 解码结果在解码器选项变更时清除重建

## 十一、关键设计特点总结

1. **双缓冲架构**：采集和显示使用独立的 SessionData，避免数据竞争

4. **Python 解码器**：通过 libsigrokdecode 调用 Python 脚本，支持 100+ 种协议解码
5. **环形缓冲区**：Loop 模式下支持连续流式采集和实时显示
6. **消息驱动**：通过 IMessageListener 和 DSV_MSG_* 消息系统实现松耦合通信
7. **无外部 API**：纯桌面应用，所有数据流在进程内完成，没有 Web/IPC 机制
8. **单线程 UI + 后台解码**：UI 在主线程，解码在独立线程，通过 Qt 信号/槽同步

### 分析

SignalData 是最顶层的抽象类，仅封装了两个核心概念：

纯虚接口：`clear()` 和 `init()`，要求子类实现数据清理与初始化。该类本身不持有任何波形数据，仅作为类型标识和公共属性的载体。

### 环形缓冲区机制

## 四、LogicSnapshot -- 逻辑信号快照

**文件**: [logicsnapshot.h](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/logicsnapshot.h), [logicsnapshot.cpp](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/logicsnapshot.cpp)

### 核心设计：多级分层索引 + Mip-map 压缩

这是三种快照中**最复杂**的数据结构，采用了类似文件系统的**多级索引树**来存储逻辑通道的位数据。

#### 关键常量

```cpp
static const uint64_t ScaleLevel = 4;       // 分层级别数
static const uint64_t ScalePower = 6;        // 每级幂次 (64)
static const uint64_t Scale = 1 << 6;        // = 64
static const uint64_t ScaleSize = Scale / 8;  // = 8 字节
static const uint64_t LeafBlockPower = ScaleLevel * ScalePower; // = 24
static const uint64_t LeafBlockSamples = 1 << 24;  // = 16,777,216 采样点/叶块
static const uint64_t RootScalePower = 6;
static const uint64_t RootScale = 64;         // 每个根节点包含64个叶块指针
static const uint64_t RootNodeSamples = LeafBlockSamples * RootScale; // = 1,073,741,824
static const uint64_t LeafBlockSpace = (64 + 64*64 + 64*64*64 + 64*64*64*64) / 8;
    // = (64 + 4096 + 262144 + 16777216) / 8 = 2,130,432 字节 ≈ 2MB
```

#### 数据结构

```cpp
struct RootNode {
    uint64_t tog;           // 变化位图：标记哪些叶块内有信号跳变
    uint64_t first;         // 每个叶块的第一个采样值位图
    uint64_t last;          // 每个叶块的最后一个采样值位图
    void *lbp[Scale];       // 64个叶块指针（按需分配）
};

std::vector<std::vector<struct RootNode>> _ch_data;  // [通道][根节点]
```

#### 内存布局

逻辑数据采用**按位存储**，每个采样点仅占 1 bit：

```
_ch_data[通道索引][根节点索引].lbp[叶块索引]
    │
    └──> LeafBlock (2,130,432 字节)
         ├── Level 0 (原始数据):  LeafBlockSamples / 8 = 2,097,152 字节
         ├── Level 1 (Mip-map):   LeafBlockSamples / Scale / 8 = 32,768 字节
         ├── Level 2 (Mip-map):   LeafBlockSamples / Scale^2 / 8 = 512 字节
         └── Level 3 (Mip-map):   LeafBlockSamples / Scale^3 / 8 = 8 字节
```

- **Level 0**：原始位数据，每 64 个采样点（1个 uint64_t）为一组
- **Level 1-3**：Mip-map 层级，每级将 64 个父级单元压缩为 1 bit（标记是否有跳变）

#### Mip-map 计算逻辑 (`calc_mipmap`)

[logicsnapshot.cpp:476-578](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/logicsnapshot.cpp#L476-L578)

1. **Level 1**：遍历 Level 0 的每个 uint64_t，与前一个 uint64_t 比较。若有差异（异或非零），在 Level 1 对应位置置 1
2. **Level 2**：遍历 Level 1 的每个 uint64_t，若非零则在 Level 2 对应位置置 1
3. **Level 3**：遍历 Level 2 的每个 uint64_t，若非零则在 Level 3 对应位置置 1

**关键优化**：若 Level 3 全零（整个叶块无跳变），且不是当前引用块，则**释放该叶块内存**，仅保留 RootNode 中的 `first`/`last` 位图用于推断恒定电平。

#### 数据写入流程 (`append_cross_payload`)

[logicsnapshot.cpp:208-438](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/logicsnapshot.cpp#L208-L438)

1. 输入数据格式为 `LA_CROSS_DATA`（交叉通道数据），即多通道数据按字节交织
2. 处理**位对齐**：处理上次遗留的非整字节/非整通道数据
3. **批量写入**：以 uint64_t（8字节 = 64采样点）为单位，按通道分离写入对应叶块
4. 每填满一个叶块（LeafBlockSamples 个采样点），调用 `calc_mipmap` 计算多级索引
5. 支持环形缓冲：当循环模式开启时，通过 `move_first_node_to_last()` 回收最旧根节点

#### 数据读取与边缘搜索

- **`get_samples()`**：通过三级索引（root_index -> lbp_index -> offset）定位叶块，返回原始数据指针
- **`get_sample()`**：获取单个采样点值。若叶块已释放（tog=0），直接从 RootNode 的 `first` 位图推断恒定电平
- **`get_nxt_edge()` / `get_pre_edge()`**：利用 Mip-map 层级进行**快速边缘跳转**，算法类似二分搜索：
  1. 在 RootNode 的 `tog` 位图中查找有跳变的叶块
  2. 在叶块内从高层 Mip-map 逐级缩小范围
  3. 最终在 Level 0 精确定位跳变位置
- **`get_display_edges()`**：为显示生成边缘序列，逐像素搜索跳变点
- **`pattern_search()`**：支持模式搜索（0/1/R上升沿/F下降沿/C任意跳变/X无关）

#### 位操作加速

内联了高效的位操作函数：
- `bsf_folded()`：查找最低有效位（使用 de Bruijn 乘法哈希表）
- `bsr32()` / `bsr64()`：查找最高有效位（使用 256 元素查找表）

## 五、AnalogSnapshot -- 模拟信号快照

**文件**: [analogsnapshot.h](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/analogsnapshot.h), [analogsnapshot.cpp](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/analogsnapshot.cpp)

### 关键数据结构

```cpp
struct EnvelopeSample {
    uint8_t min;    // 最小值
    uint8_t max;    // 最大值
};

struct Envelope {
    uint64_t length;        // 当前有效长度
    uint64_t ring_length;   // 环形缓冲位置
    uint64_t count;         // 总容量
    uint64_t data_length;   // 已分配数据长度
    EnvelopeSample *samples; // 包络样本数组
    uint8_t *max;           // 最大值数组（未使用）
    uint8_t *min;           // 最小值数组（未使用）
};

void *_data;  // 原始数据缓冲区（连续内存）
struct Envelope _envelope_levels[DS_MAX_ANALOG_PROBES_NUM][ScaleStepCount]; // 多级包络
```

### 内存布局

AnalogSnapshot 采用**连续扁平缓冲区**存储原始数据：

```
_data (总大小 = total_sample_count * channel_num * unit_bytes + sizeof(uint64_t))
├── 通道0样本0, 通道1样本0, ..., 通道N样本0,
├── 通道0样本1, 通道1样本1, ..., 通道N样本1,
├── ...
└── 通道0样本M, 通道1样本M, ..., 通道N样本M
```

- **`_unit_bytes`**：由 `analog.unit_bits` 决定，`_unit_bytes = (unit_bits + 7) / 8`
- **多通道交织存储**：每个采样点位置存储所有通道的值，步长为 `_unit_bytes * _channel_num`
- 构造时 `unit_size = sizeof(uint16_t) = 2`，但实际由 ADC 精度决定

### 包络（Envelope）Mip-map 机制

```cpp
static const unsigned int ScaleStepCount = 10;        // 10级包络
static const int EnvelopeScalePower = 4;              // 每级缩放 2^4 = 16
static const int EnvelopeScaleFactor = 16;            // 每个包络样本代表16个原始样本
```

**包络层级**：
- Level 0：每 16 个原始采样取 min/max -> 1 个 EnvelopeSample
- Level 1：每 16 个 Level 0 样本取 min/max -> 1 个 EnvelopeSample
- ...
- Level 9：最高层级，缩放因子 = 16^10 = 约 1.1 万亿

**包络计算** (`append_payload_to_envelope_levels`):

[analogsnapshot.cpp:257-349](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/analogsnapshot.cpp#L257-L349)

1. Level 0：遍历原始数据，每 `EnvelopeScaleFactor` 个采样取 min/max
2. Level 1+：从上一级包络中取 min/max，逐级递推
3. 支持环形缓冲：当数据写满一圈后，`dest_ptr` 回绕到缓冲区起始

### 数据访问

- **`get_samples(start_sample)`**：直接返回 `_data + start_sample * _unit_bytes * _channel_num`，O(1) 随机访问
- **`get_envelope_section()`**：根据 `min_length`（像素对应的最小采样长度）自动选择合适的包络层级，避免渲染时遍历过多原始数据

### 环形缓冲写入

`append_data()` 实现了环形写入：
1. 若写入后不超过总容量，直接 memcpy
2. 若超过总容量，分两段写入：先填满剩余空间，再从缓冲区起始继续写入
3. `_ring_sample_count` 以 `_total_sample_count` 取模循环

## 六、DsoSnapshot -- DSO 信号快照

**文件**: [dsosnapshot.h](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/dsosnapshot.h), [dsosnapshot.cpp](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/dsosnapshot.cpp)

### 关键数据结构

```cpp
struct EnvelopeSample {
    uint8_t min;
    uint8_t max;
};

struct Envelope {
    uint64_t length;
    uint64_t data_length;
    EnvelopeSample *samples;
};

std::vector<uint8_t*> _ch_data;  // 每通道独立缓冲区
struct Envelope _envelope_levels[2*DS_MAX_DSO_PROBES_NUM][ScaleStepCount];
bool _envelope_en;       // 包络是否启用

```

### 内存布局

与 AnalogSnapshot 不同，DsoSnapshot 采用**每通道独立缓冲区**：

```
_ch_data[0] -> [样本0, 样本1, ..., 样本N]  (通道0，每个样本1字节)
_ch_data[1] -> [样本0, 样本1, ..., 样本N]  (通道1，每个样本1字节)
...
```

- 每个通道分配 `total_sample_count + 1` 字节
- 每个采样值固定为 **1 字节 (uint8_t)**
- 通道间数据完全分离，无交织

### 数据写入 (`append_data`)

[dsosnapshot.cpp:230-260](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/data/dsosnapshot.cpp#L230-L260)

输入数据为**交织格式**（通道0样本0, 通道1样本0, 通道0样本1, ...），写入时**解交织**到各通道独立缓冲区：

```cpp
for (unsigned int ch = 0; ch < _channel_num; ch++) {
    uint8_t *src = (uint8_t*)data + ch;
    uint8_t *dest = _ch_data[ch];
    for (uint64_t i = 0; i < samples; i++) {
        *dest++ = *src;
        src += _channel_num;  // 跳过其他通道
    }
}
```

两种采集模式：
- **Instant（单次）**：`_sample_count` 累加，数据追加写入
- **非 Instant（滚动/连续）**：`_sample_count = samples`，每次覆盖整个缓冲区

### 包络机制

```cpp
static const int EnvelopeScalePower = 8;       // 每级缩放 2^8 = 256
static const int EnvelopeScaleFactor = 256;     // 每个包络样本代表256个原始样本
static const unsigned int ScaleStepCount = 10;  // 10级
```

与 AnalogSnapshot 的包络机制类似，但**缩放因子更大**（256 vs 16），因为 DSO 数据通常采样率更高、数据量更大。

**包络启用控制**：通过 `enable_envelope(bool)` 按需启用，首次启用时调用 `append_payload_to_envelope_levels(true)` 从头计算全部包络。

### 特有功能

- **`cal_vrms()`**：计算 RMS 电压值，使用增量算法避免浮点溢出，步进 `VrmsScaleFactor = 256`
- **`cal_vmean()`**：计算平均电压值
- **`get_max_min_value()`**：获取通道最大最小值
- **`get_samples(start, end, ch_index)`**：按通道索引直接返回数据指针

## 八、数据流：从采集到显示

### 1. 数据采集阶段

```
硬件采集 -> libsigrok 回调 -> sr_datafeed_logic/analog/dso
                                    │
                                    ▼
                            first_payload()  ← 首次数据，初始化缓冲区
                                    │
                                    ▼
                            append_payload() ← 后续数据追加
                                    │
                                    ├── 写入原始数据缓冲区
                                    └── 计算包络/Mip-map
```

- `first_payload()`：根据通道配置分配内存，初始化数据结构，然后调用 `append_payload()` 写入第一批数据
- `append_payload()`：加锁后写入数据并更新索引/包络

### 2. 数据存储阶段

- **Logic**：交叉数据按通道分离写入叶块，每填满叶块计算 Mip-map，无跳变叶块可被释放
- **Analog**：数据写入连续缓冲区（支持环形），同步计算包络层级
- **DSO**：交织数据解交织到各通道缓冲区，包络按需计算

### 3. 数据显示阶段

```
视图层请求 -> get_samples() / get_envelope_section() / get_display_edges()
                    │
                    ├── 缩放级别大（每像素对应少量采样）：
                    │     直接读取原始数据
                    │
                    └── 缩放级别小（每像素对应大量采样）：
                          读取包络数据（min/max 对），避免遍历全部原始数据
```

- **Logic** 显示：`get_display_edges()` 利用 Mip-map 快速定位跳变，生成边缘序列供渲染
- **Analog/DSO** 显示：`get_envelope_section()` 根据像素密度自动选择包络层级，返回 min/max 对用于绘制包络线

### 4. 循环/滚动采集

- **Logic**：`_is_loop` 标志启用循环模式，`move_first_node_to_last()` 回收最旧根节点，`free_head_blocks()` 释放已读取的叶块
- **Analog**：环形缓冲区自动覆盖旧数据
- **DSO**：非 instant 模式下每次覆盖整个缓冲区

## 九、关键设计特点

1. **惰性内存分配**：LogicSnapshot 的叶块按需分配，无跳变的叶块可释放，极大节省内存（逻辑信号常长时间保持同一电平）
2. **多级 Mip-map**：三种快照均采用多级索引/包络，实现 O(log N) 的边缘搜索和 O(1) 的显示数据提取
3. **线程安全**：所有公共方法通过 mutex 保护，支持采集线程与显示线程并发访问
4. **环形缓冲**：Snapshot 基类提供环形缓冲语义，支持滚动模式下的连续采集
5. **自适应显示**：根据缩放级别自动选择原始数据或包络数据，平衡精度与性能

- **解码任务管理**: 解码器的添加/删除/重置，解码任务队列与线程调度 (`add_decoder`, `remove_decoder`, `add_decode_task`, `decode_task_proc`)
- **信号/通道管理**: 信号创建、重载、清理 (`init_signals`, `reload`, `clear_signals`)
- **采集模式管理**: 单次/重复/循环三种模式 (`COLLECT_SINGLE`, `COLLECT_REPEAT`, `COLLECT_LOOP`)
- **双缓冲数据管理**: `_view_data` 与 `_capture_data` 的切换

### 1.2 数据采集的触发与管理

采集触发链路如下：

```
用户操作 -> start_capture(instant)
  -> action_start_capture(instant)
    -> exec_capture()
      -> capture_init()        // 初始化采样率、数据容器、定时器
      -> _device_agent.start() // 调用 libsigrok 的 ds_start_collect()
```

数据接收链路：

```
libsigrok 回调 -> data_feed_callback() [静态]
  -> data_feed_in() [加 _data_mutex 锁]
    -> 根据 packet->type 分发:
       SR_DF_HEADER  -> feed_in_header()
       SR_DF_META    -> feed_in_meta()
       SR_DF_TRIGGER -> feed_in_trigger()
       SR_DF_LOGIC   -> feed_in_logic()   -> _capture_data->get_logic()->first_payload/append_payload
       SR_DF_DSO     -> feed_in_dso()     -> _capture_data->get_dso()->first_payload/append_payload
       SR_DF_ANALOG  -> feed_in_analog()  -> _capture_data->get_analog()->first_payload/append_payload
       SR_DF_END     -> 标记采集结束，触发解码任务
       SR_DF_OVERFLOW -> 设置 Data_overflow 错误
```

### 1.3 信号/槽连接的数据流

SigSession **不使用 Qt 信号槽**，而是通过两种机制与 UI 层通信：

1. **ISessionCallback 接口** (`_callback`，实际指向 MainWindow)：直接函数调用，如 `_callback->data_updated()`, `_callback->frame_ended()`, `_callback->trigger_message(msg)` 等
2. **IMessageListener 消息广播**：`broadcast_msg(msg)` 向所有注册的监听者发送消息，包括自身 (`OnMessage`)

关键回调路径：
- `_callback->trigger_message(msg)` -> `MainWindow::trigger_message()` -> `_event.trigger_message(msg)` (Qt信号) -> `MainWindow::on_trigger_message()` -> `_session->broadcast_msg(msg)` -> 各监听者的 `OnMessage()`

### 1.4 Snapshot 与解码栈管理

**SessionData 双缓冲机制**:

```cpp
SessionData *_view_data;     // 当前显示的数据
SessionData *_capture_data;  // 当前采集写入的数据
std::vector<SessionData*> _data_list; // 两个 SessionData 对象
```

- 单次模式且流式时：`_capture_data == _view_data`（同一缓冲）
- 重复模式非流式时：交换缓冲，`_view_data = _capture_data`，旧 view 数据被清除
- `SessionData` 包含三种快照：`LogicSnapshot`, `AnalogSnapshot`, `DsoSnapshot`

**解码栈管理**:

- `_decode_traces`: 所有解码轨迹列表
- `_decode_tasks`: 等待执行的解码任务队列
- `_decode_thread`: 独立的解码线程
- `add_decode_task()`: 将 DecodeTrace 加入队列，若解码线程未运行则创建
- `decode_task_proc()`: 解码线程主循环，依次取出任务执行 `begin_decode_work()`
- 解码完成后调用 `_view_data->get_logic()->decode_end()`

### 1.5 导出/API 机制

- `get_snapshot(type)`: 按类型获取当前视图的 Snapshot 指针
- `get_signals()`: 获取信号列表引用
- `get_decode_signals()`: 获取解码轨迹列表
- `get_spectrum_traces()`: 获取频谱轨迹
- `get_math_trace()`: 获取数学运算轨迹
- `get_device_list()`: 获取设备列表
- `session_save()`: 触发回调保存会话
- `ISessionDataGetter::genSessionData()`: 生成会话 JSON 数据

## 五、EventObject -- 事件对象

**文件**: [eventobject.h](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/appcore/eventobject.h), [eventobject.cpp](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/appcore/eventobject.cpp)

### 5.1 类职责与接口

`EventObject` 和 `DeviceEventObject` 是纯 Qt 信号中转对象，用于将非 Qt 线程的回调安全地转发到 Qt 事件循环。

**EventObject 信号**:
- `show_error(QString)` -- 错误显示
- `capture_state_changed(int)` -- 采集状态变更
- `data_updated()` -- 数据更新
- `session_error()` -- 会话错误
- `signals_changed()` -- 信号列表变更
- `receive_trigger(quint64)` -- 触发位置接收
- `frame_ended()` / `frame_began()` -- 帧结束/开始
- `decode_done()` -- 解码完成
- `receive_data_len(quint64)` -- 接收数据长度
- `cur_snap_samplerate_changed()` -- 采样率变更
- `trigger_message(int)` -- 触发消息（用于跨线程消息传递）

**DeviceEventObject 信号**:
- `device_updated()` -- 设备更新

### 5.2 在数据流中的角色

EventObject 是 SigSession (工作在 libsigrok 回调线程) 与 MainWindow (Qt GUI 线程) 之间的桥梁：

```
SigSession (回调线程)
  -> ISessionCallback 方法 (如 data_updated())
    -> MainWindow::data_updated()
      -> _event.data_updated() [Qt 信号发射]
        -> MainWindow::on_data_updated() [Qt 槽，在 GUI 线程执行]
          -> _view->data_updated()
```

这种设计确保了线程安全：libsigrok 的数据回调在非 GUI 线程执行，通过 Qt 信号槽的队列连接机制安全地转到 GUI 线程。

1. **初始化检查**: 验证所有解码器已绑定必要通道，获取逻辑信号快照

6. **进度通知**: 每处理一定量数据后发射 `new_decode_data()` 信号通知 UI 刷新

**注解回调** (`annotation_callback`, 第761-818行):

这是从 libsigrokdecode 接收解码结果的关键入口：

```cpp
void DecoderStack::annotation_callback(srd_proto_data *pdata, void *self)
{
    // 1. 从 pdata 创建 Annotation 对象
```

**行构建** (`build_row`, 第142-207行):

遍历 `_stack` 中每个解码器，根据 `srd_decoder` 的 `annotation_rows` 定义创建 Row 和 RowData。如果解码器没有定义 `annotation_rows`，则创建一个默认行。同时建立 `_class_rows` 映射，将每个注解类别（ann_class）映射到对应的 Row。对于包含 "bit" 或 "warning" 的行，默认在列表视图中隐藏 (`_rows_lshow = false`)。

### 3. Annotation — 注解数据

|------|------|------|

| `_end_sample` | `uint64_t` | 注解结束采样点 |
| `_format` | `short` | 注解类别（ann_class），对应 srd_decoder 的 annotation_classes |
| `_type` | `short` | 注解类型（ann_type） |

**构造函数核心逻辑**（第41-101行）:

1. 从 `srd_proto_data` 提取 `start_sample`、`end_sample`、`ann_class`、`ann_type`
2. 将注解文本拼接为 key 字符串（跳过换行符开头的行），如有数值数据则追加十六进制字符串
3. 调用 `_status->m_resTable.MakeIndex(key, resItem)` 获取或创建资源索引
4. 如果是新条目（`resItem != NULL`），填充原始文本行 `src_lines` 和十六进制数值 `str_number_hex`
5. 设置 `_status->m_bNumeric` 标志

**`annotations()` 方法 — 按需格式转换**（第114-176行）:

这是获取注解显示文本的核心方法，实现了**惰性格式转换**：

1. 通过 `_resIndex` 从资源表获取 `AnnotationSourceItem`
2. 如果非数值型，直接返回 `src_lines`（原始文本）
3. 如果是数值型，检查 `cur_display_format` 是否与 `_status->m_format` 一致
4. 若格式不匹配，则重新转换：将 `src_lines` 中的 `{$}` 占位符替换为格式化后的数值字符串，存入 `cvt_lines`
5. 返回 `cvt_lines`

这种设计使得**切换显示格式（hex/dec/oct/bin/ascii）时无需重新解码**，只需修改 `DecoderStatus::m_format` 并重新调用 `annotations()` 即可。

### 6. AnnotationResTable — 注解资源去重与格式转换表

**文件**: [annotationrestable.h](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/decode/annotationrestable.h), [annotationrestable.cpp](file:///home/muse/workplace/PXView-PXView_v1.4.9/PXView/src/decode/annotationrestable.cpp)

**核心设计思想 — 字符串去重**:

协议解码中大量注解文本重复（如相同的寄存器名、状态描述等）。AnnotationResTable 通过 `m_indexs`（字符串→索引映射）实现去重：相同内容的注解共享同一个 `AnnotationSourceItem`，Annotation 仅存储 `_resIndex` 索引。

**`MakeIndex()` 方法**（第114-132行）:
- 查找 key 是否已存在，存在则返回已有索引
- 不存在则创建新 `AnnotationSourceItem`，追加到 `m_resourceTable`，记录索引
- 通过输出参数 `newItem` 返回新条目指针（已存在时为 NULL）

**格式转换** (`format_numberic()` / `format_to_string()`):

支持五种显示格式（由 `DisplayDataFormat` 定义）:

| 枚举值 | 格式 | 说明 |
|--------|------|------|
| `hex` (0) | 十六进制 | 默认格式，直接返回原始 hex 字符串 |
| `dec` (1) | 十进制 | 转 bin 后再转 long long，sprintf 输出 |
| `oct` (2) | 八进制 | 先转二进制字符串，再3位一组转八进制 |
| `bin` (3) | 二进制 | 使用查表法将每个 hex 字符转为 4 位二进制 |
| `ascii` (4) | ASCII | 单字节时显示字符，否则显示 [hex] |

`format_numberic()` 还支持含分隔符的复合十六进制字符串（如 `"1A:2B:3C"`），会逐段转换并保留分隔符。

## 四、解码结果的组织方式

### 按行组织 (Row-based)

解码结果的核心组织方式是**按行 (Row) 组织**。每个协议解码器可以定义多个 `annotation_rows`，每个行包含一组相关的注解类别。组织层次为：

```
DecoderStack
  └── _rows: map<Row, RowData*>
        └── RowData
              └── _annotations: vector<Annotation*>
                    └── Annotation
                          ├── 采样点范围 (_start_sample, _end_sample)
                          ├── 类别信息 (_format, _type)
                          └── 资源索引 (_resIndex) → AnnotationResTable
```

### 行的映射关系

`_class_rows` 建立了 `(srd_decoder*, ann_class)` → `Row` 的映射。当 `annotation_callback` 收到一个注解时：
1. 首先用 `(decoder, format)` 在 `_class_rows` 中查找对应的子行
2. 找不到则使用 `Row(decoder)` 查找默认行
3. 将注解推入对应行的 `RowData`

### 可见性控制

双层可见性控制：
- `_rows_gshow`: 控制行在全局（波形视图）中的显示
- `_rows_lshow`: 控制行在列表视图中的显示
- 包含 "bit" 或 "warning" 关键词的行默认在列表视图中隐藏

### 资源去重

`AnnotationResTable` 通过字符串 key 去重，相同内容的注解共享同一个 `AnnotationSourceItem`。这在协议解码中非常重要，因为大量注解具有相同的文本（如重复的寄存器地址、状态码等），去重可以显著减少内存占用。

## 五、关键设计特点总结

1. **回调驱动**: 通过 libsigrokdecode 的 `srd_pd_output_callback_add` 注册回调，解码结果以推送方式进入 DecoderStack
2. **分块处理**: 采样数据按 16KB 分块送入解码引擎，支持实时采集场景下的流式解码
3. **惰性格式转换**: 数值型注解的格式转换延迟到 `annotations()` 调用时执行，切换显示格式无需重新解码
4. **字符串去重**: AnnotationResTable 对注解文本进行去重，相同内容共享存储
5. **双缓冲设置**: Decoder 的 probes/options 采用备份-提交模式，避免解码过程中配置被修改
6. **线程安全**: RowData 使用全局静态互斥锁保护，DecoderStack 使用实例互斥锁保护 `_samples_decoded`
7. **信号通知**: 通过 Qt 信号 `new_decode_data()` 和 `decode_done()` 驱动 UI 更新

**初始化**（`init`）：

- **SR_DF_META**：提取 `SR_CONF_SAMPLERATE`、`SR_CONF_LIMIT_SAMPLES`、`SR_CONF_REF_MIN`、`SR_CONF_REF_MAX`
- **SR_DF_LOGIC**：

  - 逐采样点遍历，当 `bExportOriginalData==0` 时跳过与前次相同的采样（压缩）
  - 输出格式：`时间(秒),通道0值,通道1值,...`
  - 时间计算：`(double)(index-1) / (double)samplerate`
  - 每个通道值：按位提取，输出 '0' 或 '1'

- **SR_DF_DSO**：
  - 输出格式：`通道0电压,通道1电压,...`
  - 电压计算：`(offset - raw_value) * scale / (ref_max - ref_min)`
  - 保留5位小数

- **SR_DF_ANALOG**：
  - 输出格式：`通道0值,通道1值,...`
  - 值计算：`(offset - raw_value) * (map_max - map_min) / (ref_max - ref_min)`
  - 保留5位小数

## 六、数据提取要点总结

1. **逻辑数据提取**：从 `sr_datafeed_logic.data` 中按 `unitsize` 步长遍历，每个采样点中按位提取各通道值。位索引 = `channel_index / 8` 得到字节偏移，`channel_index % 8` 得到位偏移。

2. **DSO 数据提取**：从 `sr_datafeed_dso.data` 中按交错方式读取，偏移 = `sample_index * num_channels + channel_index`。原始字节值需经 `(offset - raw) * scale / (ref_max - ref_min)` 转换为电压。

3. **模拟数据提取**：与 DSO 类似，但转换公式为 `(offset - raw) * (map_max - map_min) / (ref_max - ref_min)`，映射范围由通道的 `map_min`/`map_max` 决定。

4. **采样率获取**：通过 `SR_DF_META` 包中的 `SR_CONF_SAMPLERATE` 配置项获取，或通过 `sr_config_get()` + `SR_CONF_SAMPLERATE` 查询。

5. **去重/压缩**：CSV 对逻辑数据支持去重（跳过与前次相同的采样），VCD 只输出信号变化（delta），Gnuplot 也去重但保留首尾采样。SRZip 存储原始数据不做去重。

6. **数据流方向**：硬件驱动 -> `ds_data_forward()` -> 用户回调 -> 输出模块 `receive()` -> 格式化输出。输出模块通过 `sr_output_send()` 接口被调用，返回 `GString*` 格式的输出文本。

   ```json
     "version": 2,
     "label": "...",
   ```

6. **`load_decoders()`** — 从 JSON 反序列化恢复解码器配置

7. **`MakeChunkName()`** — 生成 ZIP 内部数据块命名规则：

   - 版本 < 2: 固定为 `"data"`

- **保存格式**: `.pxlogic` — 本质是 ZIP 压缩包，内部包含：

# PXView 波形与解码数据提取及 Web API 方案

## 一、项目架构概览

PXView 是一个基于 Qt5 的逻辑分析仪/示波器桌面应用，核心组件：

```
┌─────────────────────────────────────────────────────────┐
│  MainWindow (Qt GUI)                                    │
│    └─ View (波形渲染)                                    │
│    └─ ProtocolDock (解码列表)                             │
│    └─ MeasureDock (测量)                                  │
├─────────────────────────────────────────────────────────┤
│  SigSession (核心会话控制器)                               │
│    ├─ DeviceAgent → libsigrok (硬件采集)                  │
│    ├─ SessionData (双缓冲: _view_data / _capture_data)    │
│    │    ├─ LogicSnapshot  (逻辑信号，多级索引树+Mip-map)    │
│    │    ├─ AnalogSnapshot  (模拟信号，连续缓冲+Envelope)    │
│    │    └─ DsoSnapshot     (示波器信号，独立通道缓冲)       │
│    ├─ DecoderStack[] (协议解码栈)                          │
│    │    └─ Row → RowData → Annotation[] (解码注解)        │
│    ├─ SpectrumStack (FFT频谱)                             │
│    └─ MathStack (数学运算)                                │
├─────────────────────────────────────────────────────────┤
│  libsigrok (C库，硬件驱动+数据采集)                        │
│  libsigrokdecode (C+Python库，协议解码)                    │
└─────────────────────────────────────────────────────────┘
```

**关键发现：项目当前没有任何网络/API层，是纯本地桌面应用。**

## 二、数据提取点分析

### 2.1 波形数据提取

| 数据类型 | 存储位置 | 数据格式 | 提取方法 |
|---------|---------|---------|---------|
| **逻辑信号** | `LogicSnapshot::_ch_data[通道][根节点].lbp[叶块]` | 按位存储(1bit/采样)，4级Mip-map | `get_samples(start, end)` 返回原始位数据指针；`get_sample(index)` 返回单点值；`get_nxt_edge()/get_pre_edge()` 边缘搜索 |
| **模拟信号** | `AnalogSnapshot::_data` | 连续缓冲区，多通道交织，unit_bytes由ADC精度决定 | `get_samples(start)` 直接偏移访问 O(1) |
| **DSO信号** | `DsoSnapshot::_ch_data[通道]` | 每通道独立缓冲区，uint8_t/采样 | `get_samples(start, end, ch_index)` 按通道直接访问 |
| **包络数据** | `AnalogSnapshot/DsoSnapshot::_envelope_levels[通道][层级]` | 10级min/max包络 | `get_envelope_section(start, end, min_length)` 自动选择层级 |
| **频谱数据** | `SpectrumStack::_power_spectrum` | `vector<double>`，大小为sample_num/2+1 | `get_fft_spectrum()` 返回功率谱向量 |
| **数学运算** | `MathStack::_math` | `vector<double>` | `get_math(start)` 返回结果指针 |

**核心入口**：通过 `SigSession::get_snapshot(type)` 获取当前视图的 Snapshot 指针。

### 2.2 解码数据提取

| 数据 | 存储位置 | 提取方法 |
|------|---------|---------|
| **注解列表** | `DecoderStack::_rows: map<Row, RowData*>` → `RowData::_annotations: vector<Annotation*>` | `get_annotation_subset(row, start, end)` 按范围获取；`list_annotation(row_idx, col_idx)` 按索引获取 |
| **注解内容** | `Annotation::_resIndex` → `AnnotationResTable` | `Annotation::annotations()` 返回格式化文本行 |
| **行信息** | `DecoderStack::_rows` / `_class_rows` | `list_row_title()`, `list_rows_size()`, `list_annotation_size()` |
| **格式转换** | `DecoderStatus::m_format` + `AnnotationResTable` | 修改 `m_format` 后重新调用 `annotations()` 即可切换 hex/dec/oct/bin/ascii |

### 2.3 缓存/双缓冲机制

```
SigSession 持有两个 SessionData:
  _view_data     ← 当前显示的数据（UI读取此缓冲）
  _capture_data  ← 当前采集写入的数据（采集线程写入此缓冲）

单次模式(流式): _capture_data == _view_data (同一缓冲)
重复模式(非流式): 采集结束后交换，_view_data = _capture_data
```

**提取当前有效数据**：始终从 `_view_data` 读取即可获得最新完整波形。

## 三、Web API 方案设计

### 3.1 技术选型

推荐使用 **Qt 内置的 `QHttpServer`**（Qt 5.12+ 实验性模块，Qt 6.x 正式模块），或更成熟的第三方方案：

| 方案 | 优点 | 缺点 |
|------|------|------|
| **QHttpServer** (Qt5) | 与现有Qt生态一致，无额外依赖 | Qt5中是实验模块，需单独编译 |
| **cpp-httplib** (header-only) | 零依赖，单头文件，轻量级，支持HTTPS | 非Qt原生 |
| **Pistache** | 现代C++ REST框架 | 依赖较多 |
| **QWebSocketServer** | 支持实时推送，适合波形流 | 仅WebSocket，无REST |

**推荐方案：cpp-httplib** — 单头文件引入，无需修改CMake依赖链，同时提供HTTP REST和SSE(Server-Sent Events)支持。

#### 1. 线程安全数据提取

```cpp
class DataExtractor {
    SigSession* _session;
    
    json extract_logic_edges(uint64_t start, uint64_t end, int min_period) {
        auto* snap = _session->get_snapshot(SR_CHANNEL_LOGIC);
        auto* logic = dynamic_cast<LogicSnapshot*>(snap);
        if (!logic) return {};
        
        std::lock_guard<std::mutex> lock(logic->mutex());
        
        json result;
        // 利用 LogicSnapshot 已有的 get_nxt_edge() 高效提取边缘
        for (int ch = 0; ch < logic->get_channel_num(); ch++) {
            uint64_t pos = start;
            while (pos < end) {
                uint64_t edge = logic->get_nxt_edge(pos, ch, end);
                if (edge >= end) break;
                bool value = logic->get_sample(edge, ch);
                result["channels"][ch]["edges"].push_back({
                    {"sample", edge}, {"value", value}
                });
                pos = edge + 1;
            }
        }
        return result;
    }
    
    json extract_analog(int channel, uint64_t start, uint64_t end) {
        auto* snap = _session->get_snapshot(SR_CHANNEL_ANALOG);
        auto* analog = dynamic_cast<AnalogSnapshot*>(snap);
        if (!analog) return {};
        
        std::lock_guard<std::mutex> lock(analog->mutex());
        
        // 根据数据量选择原始数据或包络
        uint64_t sample_count = end - start;
        if (sample_count > 10000) {
            return extract_analog_envelope(analog, channel, start, end);
        }
        
        // 直接读取原始数据
        auto* data = (uint8_t*)analog->get_samples(start);

    }
};
```

## 四、数据提取关键路径总结

### 从缓存中提取波形的完整调用链

```
1. 获取 Session:
   AppControl::Instance()->GetSession()

2. 获取 Snapshot:
   SigSession::get_snapshot(SR_CHANNEL_LOGIC/ANALOG/DSO)
     → _view_data->get_logic()/get_analog()/get_dso()

3. 逻辑信号提取:
   LogicSnapshot::get_nxt_edge(pos, ch_index, end)  // 边缘搜索
   LogicSnapshot::get_sample(index, ch_index)         // 单点值
   LogicSnapshot::get_samples(start, end)             // 原始数据块

4. 模拟/DSO信号提取:
   AnalogSnapshot::get_samples(start)                 // 原始数据指针
   AnalogSnapshot::get_envelope_section(start, end, min_length)  // 包络
   DsoSnapshot::get_samples(start, end, ch_index)     // 按通道数据

5. 解码数据提取:
   SigSession::get_decode_signals()                   // 获取 DecodeTrace 列表
   DecodeTrace::decoder_stack()                       // 获取 DecoderStack
   DecoderStack::list_rows_size()                     // 行数
   DecoderStack::list_row_title(row, title)           // 行标题
   DecoderStack::get_annotation_subset(row, start, end) // 范围注解
   Annotation::annotations()                          // 注解文本(支持格式转换)
```
