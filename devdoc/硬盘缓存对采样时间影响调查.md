## 调查报告：硬盘缓存启用后 Stream 模式采样时间不变的问题

### 一、问题描述

用户在 **DeviceOption** 中将设备设为 **Stream 模式**，并**启用硬盘缓存（Disk Cache）**，但界面显示的采样时间上限（如 "125MHz 1.15min"）与未启用硬盘缓存时完全一致，没有因为磁盘缓存的额外空间而增大。

---

### 二、根本原因

**采样时间显示的 UI 层（SamplingBar / DeviceAgent）完全不知道硬盘缓存的存在。** 硬盘缓存的配置仅在捕获启动时由 `SigSession` 使用，但从不反馈给 UI 层去更新采样时间的计算。

具体来说有三个独立的原因共同导致此问题：

调查报告已完成。核心结论是：

**UI 层的采样时间计算（SamplingBar + DeviceAgent）完全不知道硬盘缓存的存在。** 

具体原因有三：
1. **SamplingBar** 在生成采样时长下拉选项时，stream 模式的软件缓冲限制被刻意注释掉了（"取消流模式软件buff大小限制"），导致最大时长退化为基于硬件 FIFO 缓冲区的计算，而不是 16GB 的软件缓冲或更大的磁盘缓存。
2. **DeviceAgent::get_sample_time()** 直接读取硬件驱动的 `SR_CONF_LIMIT_SAMPLES`，不检查 `SR_CONF_DISK_CACHE_ENABLE` 或 `SR_CONF_STREAM_BUFF`。
3. **SigSession** 仅在捕获启动时（而非 UI 配置阶段）将磁盘缓存配置传给数据层，且从不反馈给 UI 刷新显示。

修复方向：在 `SamplingBar::update_sample_count_selector()` 中，当检测到 stream 模式 + 磁盘缓存启用时，应使用 `SR_CONF_STREAM_BUFF` 的值来替代 `hw_depth` 计算最大采样时长。

## 1. hw_depth 值（SR_CONF_HW_DEPTH）

**原始 hw_depth 定义在 `PX_caps` 结构体的 `hw_depth` 字段中**，通过 `supported_PX[]` 数组初始化。`SR_Gn(n)` 宏展开为 `n * 1000000000ULL`（即 n Giga-samples 的位深度）。

不同设备型号的 hw_depth 值如下：

| 设备型号 | logic_mode | hw_depth | 含义 |
|----------|-----------|----------|------|
| PX-Logic U3/U2 channel 32 (旧VID) | 0 | `SR_Gn(4)` = **4,000,000,000 bits** | 4Gbit |
| PX-Logic U3/U2 channel 32 (新VID) | 0 | `SR_Gn(4)` = **4,000,000,000 bits** | 4Gbit |
| PX-Logic U3/U2 channel 16 Pro | 1 | `SR_Gn(4)` = **4,000,000,000 bits** | 4Gbit |
| PX-Logic U3/U2 channel 16 Plus | 2 | `SR_Gn(2)` = **2,000,000,000 bits** | 2Gbit |
| PX-Logic U3/U2 channel 16 Base | 3 | `SR_Gn(1)` = **1,000,000,000 bits** | 1Gbit |

**实际返回给上层的 HW_DEPTH 值**（`config_get` 中 `SR_CONF_HW_DEPTH` 分支，第1053-1065行）会根据操作模式进行换算：

- **Buffer 模式**：`hw_depth / unit_bits / ch_num`（按通道数均分后的每通道采样深度）
- **Stream 模式 + 磁盘缓存开启**：`stream_buff_size * 1024 * 1024 * 1024 * 8 / unit_bits / ch_num`
- **Stream 模式 + 无磁盘缓存**：与 Buffer 模式相同，使用 `hw_depth / unit_bits / ch_num`

例如，channel 32 设备在 32 通道 Buffer 模式下：`4,000,000,000 / 1 / 32 = 125,000,000` 采样点/通道。
