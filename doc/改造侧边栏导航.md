## Spec 1: `create-unified-sidebar-component` -- Unified SideBar Component Refactoring

### Goal

Create a single, unified `SideBar` widget class to replace the scattered sidebar button management across `TrigBar` and `SamplingBar`, which currently use `QToolBar` with individual `addAction` calls.

### Key Design Decisions

1. **New class** **`pv/widgets/sidebar.h/.cpp`**: `SideBar` inherits `QWidget` + `IUiWindow`, uses `QVBoxLayout` instead of `QToolBar` for full layout control (grouping, separators, custom spacing).
2. **Two button types**:
   - **`DockItem`**: Checkable, mutually exclusive (Trigger, Decode, Measure, Search, Options). Clicking one deselects all others. Clicking a checked one deselects it.
   - **`ActionItem`**: Non-checkable, independent triggers (Run/Stop, Instant). No effect on other buttons.
3. **SideBar API**:
   - `addItem(icon, textId, defaultText, itemType)` -- returns index
   - `addSeparator()` -- horizontal divider
   - `setItemVisible()`, `setItemEnabled()`, `setItemChecked()`, `clearAllChecked()`
   - Signals: `dockItemClicked(int index)`, `actionItemClicked(int index)`
4. **IUiWindow support**: `UpdateLanguage()`, `UpdateTheme()`, `UpdateFont()` for all buttons.
5. **TrigBar slimmed down**: All sidebar buttons (`_trig_button`, `_protocol_button`, `_measure_button`, `_search_button`, `_function_button`, `_setting_button`) and their QActions, signals, slots, and mutual-exclusion logic are **removed**. Only Function menu, Display menu, and theme switching remain.
6. **SamplingBar slimmed down**: Sidebar buttons (`_configure_button`, `_run_stop_button`, `_instant_button`) and their QActions and `sig_device_options(bool)` signal are **removed**. Only sampling parameter logic remains. Public methods `config_device()`, `run_or_stop()`, `run_or_stop_instant()` are preserved for SideBar to call.
7. **MainWindow changes**:
   - `_right_tool_bar` (QToolBar) replaced by `_side_bar` (SideBar)
   - `setupRightToolBar()` replaced by `setupSideBar()` using `addItem()`
   - Old individual slots (`on_protocol`, `on_trigger`, `on_measure`, `on_search`, `on_device_options`) replaced by `on_side_bar_dock_clicked(int)` and `on_side_bar_action_clicked(int)`
   - DockOptions mutual-exclusion logic moved from TrigBar's scattered clicked() slots into SideBar internally
   - SlidingDrawer close callback calls `_side_bar->clearAllChecked()`

## Relationship Between the Two Specs

These two specs are **closely related and partially overlapping**:

- **Spec 2** (`convert-deviceoptions-to-sidebar`) was planned first and adds a 5th mutually-exclusive button (`_device_options_button`) to `TrigBar`, extending the existing 4-button pattern.
- **Spec 1** (`create-unified-sidebar-component`) is a broader refactoring that **removes all sidebar buttons from TrigBar and SamplingBar entirely**, consolidating them into a single `SideBar` class. This supersedes the TrigBar changes from Spec 2.
- The spec for `create-unified-sidebar-component` explicitly notes that it impacts `convert-deviceoptions-to-sidebar` (the TrigBar button-related parts need adaptation).
- After Spec 1 is applied, the `_device_options_button` that Spec 2 added to TrigBar would no longer exist in TrigBar -- it would instead be a `DockItem` in the unified `SideBar`. The `DeviceOptionsDock` class and its QDockWidget container from Spec 2 would still be needed, but the button management moves to SideBar.

In essence, Spec 1 absorbs the button-management aspects of Spec 2, while the DeviceOptionsDock panel itself (the actual sidebar content widget) remains a separate concern from Spec 2 that would be wired up through the unified SideBar's `dockItemClicked` signal.

4. Sets the text using the localization macro `L_S(STR_PAGE_TOOLBAR, textId, defaultText)`.

6. Connects the button's `clicked` signal to `SideBar::onButtonClicked`.
7. Stores the item info and returns the auto-incrementing index.

**Button click handling** (lines 89-109): When a button is clicked, if it is a `DockItem`, all other DockItem buttons are unchecked and `dockItemClicked(index)` is emitted. If it is an `ActionItem`, `actionItemClicked(index)` is emitted.
