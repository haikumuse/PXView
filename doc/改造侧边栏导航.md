- ✅ indicator 显示/隐藏瞬间完成（减少了动画数量）

**仍存在的问题**：
- ⚠️ indicator 滑动动画使用 `QParallelAnimationGroup` + `QSequentialAnimationGroup`，层级较深
- ⚠️ 每次 tick 都调用 `setGeometry()` → `update()`，重绘频率高
- ⚠️ `ScaleSlideAnimation` 的 `valueChanged` 信号连接到 lambda，每次触发都调用 `show()` 和 `raise()`

---

### 进一步优化建议

如果仍感觉卡顿，可以考虑：

**1. 减少 indicator 动画复杂度**

将 `QParallelAnimationGroup` + `QSequentialAnimationGroup` 简化为单个 `QPropertyAnimation`：

```cpp
// 简化：只使用一个动画同时改变位置和大小
QPropertyAnimation *ani = new QPropertyAnimation(this, "geometry");
ani->setDuration(300);
ani->setStartValue(startRect);
ani->setEndValue(endRect);
ani->setEasingCurve(QEasingCurve::OutCubic);
ani->start();
```

**2. 使用 `QGraphicsEffect` 或 `QML` 进行 GPU 加速渲染**

如果 Qt 版本支持，可以使用 `QGraphicsOpacityEffect` 或迁移到 QML 的 `NumberAnimation`。

**3. 限制重绘频率**

在 `valueChanged` 处理中增加节流逻辑：

```cpp
connect(_scaleAni, &ScaleSlideAnimation::valueChanged, this,
        [this](const QRectF &g) {
          // 只在几何真正改变时才更新
          if (geometry() != g.toRect()) {
            setGeometry(g.toRect());
          }
        });
```

**4. 使用 `QAnimationDriver` 自定义刷新率**

```cpp
// 降低动画刷新率到 30fps，减少 CPU 占用
QAnimationDriver *driver = new QAnimationDriver();
driver->setRefreshRate(30);
QAnimationDriver::install(driver);
```

---

### 结论

当前代码的动画竞争已经比最初版本好很多，但**由于 Qt 的动画机制限制，所有动画本质上都在主线程执行**。如果 drawer 动画仍感觉卡顿，建议：

1. **优先简化 indicator 动画**（减少动画对象数量）
2. **测试单独运行 drawer 动画**（注释掉 indicator 动画，看是否还卡）
3. **考虑使用平台原生动画**（如 Windows 的 `SetWindowPos`  with `SWP_ASYNCWINDOWPOS`）
