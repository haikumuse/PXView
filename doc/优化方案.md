你遇到的这个问题非常典型！在处理大量数据时（比如逻辑分析仪的搜索结果），QTableWidget 是绝对的性能杀手。

为什么会卡顿且有显示上限？

QTableWidget 的机制是为每一个单元格创建一个 QTableWidgetItem 对象。如果你搜索到了 10 万条结果，3列就是 30 万个对象。这不仅会消耗海量内存，还会导致 UI 渲染线程彻底卡死，甚至因为超出系统或 Qt 的底层限制（比如布局限制或 GDI 对象上限）而导致只能显示几千行（你的情况是 4400 行）。

目前的源码尝试用 _table_fill_timer 进行“分批加载 (Batch Fill)”来缓解卡顿，但这治标不治本，对象数量依然在爆炸。

终极解决方案：使用 QTableView + QAbstractTableModel

在 Qt 中处理大数据列表的最佳实践是 Model/View 架构。

通过自定义一个 Model，直接读取你现有的 _search_results 内存（std::vector）。QTableView 只会为当前屏幕上可见的几十行数据进行绘制。无论你的结果是 1 万条还是 1000 万条，内存占用几乎为零增加，滑动如丝般顺滑，且没有显示行数上限。

1. 实现 Model (放在 searchdock.cpp 开头)

C++



namespace pv {namespace dock {



SearchResultModel::SearchResultModel(std::vector<SearchData>& results, std::mutex& mutex, QObject *parent)

    : QAbstractTableModel(parent), _results(results), _mutex(mutex), _current_count(0) {}int SearchResultModel::rowCount(const QModelIndex &/*parent*/) const {

    return _current_count; // 返回我们已知的数量，避免锁竞争导致 UI 卡顿

}int SearchResultModel::columnCount(const QModelIndex &/*parent*/) const {

    return 3;

}QVariant SearchResultModel::data(const QModelIndex &index, int role) const {

    if (!index.isValid() || role != Qt::DisplayRole)

        return QVariant();



    int row = index.row();

    int col = index.column();



    std::lock_guard<std::mutex> lock(_mutex);

    if (row >= (int)_results.size())

        return QVariant();



    const SearchData &sd = _results[row];



    if (col == 0) return QString::number(row + 1);

    if (col == 1) return QString::number(sd.start);

    if (col == 2) return QString::number(sd.end - sd.start + 1);



    return QVariant();

}QVariant SearchResultModel::headerData(int section, Qt::Orientation orientation, int role) const {

    if (role != Qt::DisplayRole || orientation != Qt::Horizontal)

        return QVariant();



    if (section == 0) return "#";

    if (section == 1) return QString(L_S(STR_PAGE_DLG, S_ID(IDS_DLG_SEARCH_COL_START), "Start"));

    if (section == 2) return QString(L_S(STR_PAGE_DLG, S_ID(IDS_DLG_SEARCH_COL_LENGTH), "Length"));



    return QVariant();

}// 安全地通知 View 数据增加了void SearchResultModel::updateRowCount(int newCount) {

    if (newCount > _current_count) {

        beginInsertRows(QModelIndex(), _current_count, newCount - 1);

        _current_count = newCount;

        endInsertRows();

    } else if (newCount == 0 && _current_count > 0) {

        beginResetModel();

        _current_count = 0;

        endResetModel();

    }

}

// 1. 新增 UI 刷新函数 (替换掉原来的 fill_table_batch)void SearchDock::refresh_ui_model(){

    _results_mutex.lock();

    int current_size = (int)_search_results.size();

    _results_mutex.unlock();



    _result_model->updateRowCount(current_size);

}// 2. 修改 start_search_asyncvoid SearchDock::start_search_async(){

    stop_search();



    _results_mutex.lock();

    _search_results.clear();

    _results_mutex.unlock();



    _result_model->updateRowCount(0); // 清空 UI



    _search_state.store(1);

    _search_future = QtConcurrent::run(this, &SearchDock::search_worker);

    _search_watcher.setFuture(_search_future);



    _ui_refresh_timer->start();

}// 3. 修改 on_search_finishedvoid SearchDock::on_search_finished(){

    if (_ui_refresh_timer->isActive())

        _ui_refresh_timer->stop();



    // 确保最后一次数据更新到了 UI

    refresh_ui_model();

}// 4. 修改点击事件 (参数变为 QModelIndex)// 注意：记得在 searchdock.h 中把 on_result_clicked(int, int) 改为 on_result_clicked(const QModelIndex&)void SearchDock::on_result_clicked(const QModelIndex& index){

    if (!index.isValid()) return;

    int row = index.row();



    _results_mutex.lock();

    if (row >= 0 && row < (int)_search_results.size()) {

        int64_t start_pos = _search_results[row].start;

        _results_mutex.unlock();

        _view->set_search_pos(start_pos, true);

    } else {

        _results_mutex.unlock();

    }

}

优化带来的好处：

彻底解决卡顿： 删除了所有 new QTableWidgetItem 的操作。内存占用极低，搜索线程跑得有多快，数据就能无缝衔接。

打破 4400 行限制： QTableView 理论上可以显示 INT_MAX（约21亿）行数据，因为底层根本没有为每一行创建真实的 UI 组件，仅仅是画在了画板上。

精简了代码逻辑： 你可以把所有为了“分批加载”而写的意大利面条代码（kBatchSize, _table_fill_index, _table_fill_timer）全部删掉。
