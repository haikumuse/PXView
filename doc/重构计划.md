✦ 为了彻底解决当前多标签架构中存在的“数据耦合、生命周期混乱、快照开销大”等缺陷，我们需要放弃目前“伪快照隔离”的补丁式做法
  ，对底层架构进行一次从“单体紧耦合”到“文档-视图（Document-View）”模型的范式重构。

  以下是为您设计的完善多标签架构方案：

  ---

  一、 核心架构设计：文档-视图分离 (MVC 模型)

  当前最大的痛点是 View、Signal (UI元素) 和 SigSession (硬件控制+数据) 深度绑定。新架构必须将其严格拆分：

   1. SessionDocument (数据模型/文档)
      - 职责：纯粹的数据容器。存储一次采集或一个加载文件对应的所有数据（LogicData, AnalogData, DsoData, DecodeData）。
      - 特点：完全不包含任何 Qt UI 元素（如 View::Signal）。独立于视图存在。

   2. SessionContext (会话上下文/Tab载体)
      - 职责：代表一个标签页（一次独立会话）的完整生命周期。
      - 内容：1个 SessionDocument (数据) + 1个 View (渲染层) + 状态数据（如当前缩放比例 scale、偏移量
        offset、光标位置）。
      - 机制：View 根据 SessionDocument 的数据，动态生成属于自己的 View::Signal 对象进行渲染。不同 Tab 拥有各自独立的
        Signal 实例，从根本上解决互相干扰和 DSO 同步变化的问题。

   3. SigSession (硬件控制器)
      - 职责：退化为纯粹的硬件管家与数据路由。
      - 机制：它不再长期持有所有数据，而是负责控制
        DeviceAgent。在采集（Capture）进行时，它将从硬件获取的数据流，实时“路由/注入”到当前处于 LIVE 状态的
        SessionDocument 中。

  ---

  二、 零拷贝的标签切换 (Zero-Copy Tab Switching)

  废除当前饱受诟病的 capture_snapshot （每次切标签都需要进行耗时且容易崩溃的内存深拷贝）。

   * 实时转历史：当在标签 A 采集完毕，或用户切换到标签 B 时。标签 A 的状态自动从 LIVE 转为 HISTORICAL。它的
     SessionDocument 停止接收新数据。
   * 无感切换：点击标签 B 时，主窗口仅仅是把中央控件（CentralWidget）切换为标签 B 所属的 View。
   * 优势：无任何数据拷贝动作！ 每个标签页从创建起就自带独立的 SessionDocument 内存池。无论是 1MB 还是 1GB
     的采集数据，标签切换都在 1 毫秒内完成，且无内存泄漏风险。

  ---

  三、 安全的窗口分离与生命周期管理

  修复目前拖拽出独立窗口（Detach）即导致对象销毁的严重 Bug，引入全局管理器：

   1. SessionManager (全局会话管理器)
      - 维护一个全局的 std::vector<SessionContext*>。无论是停留在 QTabWidget
        里的标签，还是被拖出成独立浮动窗口的视图，其 SessionContext 的生命周期都由 SessionManager 统一管理。

   2. 安全的 Detach / Attach 流程
      - 拖出 (Detach)：从 QTabWidget 移除 View，放入新建的 QMainWindow（浮动窗口）中。关键：绝对不删除 SessionContext。
      - 还原 (Attach)：关闭浮动窗口时，拦截 Close 事件，将 View 重新塞回主窗口的 QTabWidget。
      - 销毁 (Close)：只有当用户明确点击“关闭标签”按钮时，SessionManager 才会真正 delete SessionContext
        并释放关联的内存和解码线程。

  ---

  四、 动态上下文绑定的 Dock 与 Toolbar

  为了解决工具栏和停靠窗口（Measure, Search, Protocol）无法适配多标签及浮动窗口的问题：

   1. 实现 IContextAware 接口
      - 所有 Dock 和 Toolbar 实现一套标准接口：

   1      virtual void bind_context(SessionContext* ctx) = 0;
   2      virtual void unbind_context() = 0;
   2. 焦点追踪 (Focus Tracking)
      - MainWindow 监听标签的切换，以及浮动窗口的焦点变化（QApplication::focusChanged）。
      - 当标签 A 获得焦点：主窗口调用所有 Dock 的 unbind_context() 断开之前的信号，然后调用 bind_context(A_ctx)。Dock
        窗口立即读取 A 的 SessionDocument 刷新内容，并监听 A 的 View 游标变化。
   3. 全局与局部 Toolbar 分离
      - SamplingBar (采样设置)：与硬件强绑定。如果当前选中的标签是历史数据（HISTORICAL），SamplingBar
        应变为“只读模式”或显示历史参数；如果要发起新采集，点击“Start”会自动创建一个新的 LIVE 标签页，并绑定路由。

  ---

  五、 内存与状态的现代化重构 (解决底层隐患)

   1. 废弃 Raw Pointer 深拷贝：将 LogicSnapshot 等底层数据结构中大量使用的 malloc/free 替换为 C++11 标准的
      std::vector<uint8_t> 或 std::unique_ptr。结合 Move Semantics (移动语义)，防止由于异常导致的内存泄漏。
   2. 解码任务 (DecodeTask) 的归属：协议解码不应该由 SigSession 集中处理。每个 SessionDocument
      应该拥有自己的解码器栈（DecoderStack）。这样即使标签在后台，解码也能独立继续，不会互相阻塞。

  ---

  重构落地的步骤建议（平滑过渡）：
   1. Phase 1 (数据容器剥离)：切断 View::Signal 与全局 SigSession 的强耦合，让 View 自己管理渲染用 Signal。
   2. Phase 2 (引入 Context 概念)：实现 SessionContext，取消 capture_snapshot。通过指针切换替换内存深拷贝。
   3. Phase 3 (生命周期与事件修正)：引入 SessionManager，重写 QTabWidget 的拖拽逻辑，实现 Dock 窗口的动态 bind/unbind。
完善的实施计划（分为 4 个主要阶段）：

  阶段一：基础数据容器剥离 (Foundation & Decoupling)
  目标：打破 View、Signal 与全局 SigSession 的强耦合，将数据与视图解耦。

   1. 引入 SessionDocument
      - 新建 SessionDocument 类（继承并取代现有的 SessionSnapshot 功能），作为纯粹的数据容器。
      - 将 LogicSnapshot、AnalogSnapshot、DsoSnapshot 移入 SessionDocument。
      - 彻底移除容易引发内存泄漏的 capture_snapshot 深拷贝逻辑。
   2. 重构 View 和 Signal 的所有权
      - 目前 View::Signal 是由 SigSession 创建并持有的，这是导致 DSO 信号互相干扰的元凶。
      - 修改：让 View 自己负责创建和管理其内部渲染所需的 LogicSignal、AnalogSignal、DsoSignal。
      - View 仅依赖 SessionDocument 提供的数据指针进行绘制，不再依赖 SigSession。
   3. 改造 DataSource 接口
      - 梳理现有的 DataSource 接口，去除其中与 UI 强相关的冗余方法，确保其只提供纯粹的快照数据访问。

  阶段二：零拷贝上下文与管理器 (Zero-Copy Context)
  目标：实现秒级的无缝标签切换，废除旧版的强制快照归档逻辑。

   1. 完善 SessionContext
      - 丰富 TabContext（改名为 SessionContext 更符合架构），使其持有独立的 SessionDocument 和 View。
      - 引入生命周期状态机：LIVE（正在硬件采集）、HISTORICAL（历史/文件数据）。
   2. 引入全局 SessionManager
      - 创建 SessionManager 单例或由 AppControl 持有，统一管理所有 SessionContext 的列表。
      - 负责分配 Session ID，处理新建、关闭、加载文件等全局逻辑。
   3. 零拷贝切换逻辑
      - 改造 MainWindow::on_tab_changed。切换标签时，不再触发任何 capture_snapshot 或数据拷贝。仅仅是通知 UI 切换显示的
        View 控件。

  阶段三：安全的窗口分离与组件动态绑定 (Safe Detach & Dynamic Binding)
  目标：解决拖拽崩溃问题，让所有的 Dock（测量、协议等）和 Toolbar 能智能适配多标签。

   1. 重写拖拽分离 (Detach/Attach) 逻辑
      - 修改 MainWindow::on_tab_detach：当标签被拖出时，绝不 delete Context。只将 View 移动到新建的浮动 QMainWindow 中。
      - 监听浮动窗口的关闭事件，实现无损的 Attach 还原逻辑。
   2. 实现 IContextAware 接口
      - 创建 IContextAware 接口，包含 bind_context() 和 unbind_context()。
      - 让 MeasureDock、SearchDock、ProtocolDock、SamplingBar 实现该接口。
   3. 焦点追踪 (Focus Tracking)
      - 在 MainWindow 中实现全局焦点监控。当用户点击某个标签或激活某个浮动窗口时，自动触发所有 IContextAware 组件的
        unbind -> bind(new_ctx) 流程，实现侧边栏内容的秒切。

  阶段四：硬件路由与解码任务隔离 (Hardware Routing & Decoder Isolation)
  目标：确保后台标签的解码任务能继续运行，且硬件实时采集数据精准注入正确的标签。

   1. 硬件数据路由 (Hardware Routing)
      - 改造 SigSession 的底层数据回调（data_feed_callback）。
      - 当硬件数据涌入时，SigSession 查找当前处于 LIVE 状态的 SessionContext，将其数据直接写入对应的 SessionDocument
        中，并仅通知该 Context 的 View 刷新。
   2. 解码任务 (DecoderStack) 下放
      - 当前所有解码任务都集中在 SigSession 内部，这会导致历史标签的解码无法独立进行。
      - 将 DecodeTask 和 DecoderStack 从 SigSession 迁移到 SessionContext（或
        SessionDocument）中。每个标签拥有自己独立的解码线程和数据栈。
